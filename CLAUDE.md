# CLAUDE.md — контекст проекта для Claude Code

Этот файл Claude Code читает автоматически в начале каждой сессии. Держи его в
актуальном состоянии — и любая новая сессия сразу понимает проект.

## Что это за приложение
**«Дом!»** — семейный менеджер домашних дел (PWA). Собран на движке приложения
**«Соберись!»** (https://github.com/faxbax-ctrl/abkhazia-checklist): тот же вход,
хранение, синхронизация, перетаскивание и bottom-sheet. Отличается принцип
организации (хаб категорий вместо поездок), дизайн, иконки вместо эмодзи и новые
фичи (Inbox, «На выходные», приоритеты).

- Firebase-проект: `abkhazia-checklist` (общий с «Соберись!»), но **отдельный документ**.
- Открывается как приложение на iPhone/Android и в браузере, работает офлайн,
  синхронизируется между устройствами и пользователями. Вход — Google.
- **Живой адрес:** https://faxbax-ctrl.github.io/dom-tasks/
- **Репозиторий:** https://github.com/faxbax-ctrl/dom-tasks (публичный, GitHub Pages).
- **Статус:** задеплоено; документ `checklists/home` уже наполнен реальными задачами
  (пользовательский контент вносится через интерфейс, в коде/репозитории его нет).

## Технологии (НЕТ сборки, НЕТ фреймворков)
- Один статический сайт: `index.html` — весь HTML, CSS и JS.
- PWA: `manifest.webmanifest` + `sw.js` (офлайн-кэш) + иконки `icon-*.png`.
- Firebase (модульный SDK v10 через CDN): Auth (Google) + Firestore (хранение/синхр.).
- Хостинг: GitHub Pages (ветка `main`, корень). Правки — прямо в файлах, без `npm build`.

## Карта файлов
- `index.html` — приложение целиком (экран входа, рендер, логика, синхронизация,
  внизу — `<script type="module">` с инициализацией Firebase).
- `sw.js` — service worker, офлайн-кэш оболочки.
- `manifest.webmanifest` — манифест PWA (имя «Дом!», иконки, `theme_color:#37478f`).
- `icon-180/192/512.png` — иконки (генерируются из `icon.svg`).
- `icon.svg` — исходник иконки (домик на индиго). Регенерация PNG:
  `rsvg-convert -w 512 icon.svg -o icon-512.png` (и 192, 180).
- `CLAUDE.md` — этот файл. `README.md` — краткое описание и доступ.

## Модель данных
Корень — `STATE`, один уровень категорий (никаких поездок/шаблонов):
```
STATE = { v:1, cats: [
  { key, icon, color, tab, title, intro, kind, groups: [
      { emo, title, items: [ { id, t, n, done, pri, wk } ] }   // подкатегория
      | { sub }                                                // заголовок-раздел
  ] }
] }
```
- **Категория** `{key, icon, color, tab, title, intro, kind, groups}`:
  - `icon` — id иконки из карты `P` (НЕ эмодзи), `color` — акцентный цвет (`CAT_COLORS`),
  - `tab` — короткая подпись, `title` — полное имя,
  - `kind:'inbox'` — служебная категория Inbox (см. ниже). Обычные — без `kind`.
- **Подкатегория** `{emo, title, items}` — `emo` тоже id иконки (имя историческое).
- **Заголовок-раздел** `{sub}` — строка без пунктов.
- **Задача** `{id, t, n, done, pri, wk}`:
  - `t` заголовок, `n` комментарий, `done` галочка,
  - `pri` — приоритет: `''` | `'red'`(🔴 срочно) | `'orange'`(важно) | `'fast'`(⚡ быстро) | `'green'`(потом),
  - `wk` — флаг «На выходные» (`true/false`).
- **Inbox** — реальная категория `kind:'inbox'`, всегда первая, удалить нельзя
  (`ensureInbox()`; в профиле у неё нет кнопки удаления). Быстрый ввод (FAB) кладёт сюда.
- **«На выходные»** — виртуальная витрина (`active='__wk__'`), НЕ хранится в `cats`.
  Собирает все задачи с `wk===true`, сгруппированные по категории (`weekendItems()`).
  Галочка/снятие флага действуют на оригинал.
- `MODEL` = `STATE.cats`; `active` — `null`(хаб) | `'__wk__'`(выходные) | ключ категории.
- **Миграция** `migrate()` идемпотентна: старый/пустой формат заворачивается в `{v:1,cats:[]}`,
  гарантируется Inbox, старым задачам проставляются `pri:''`/`wk:false`.
- Облако: один документ **`checklists/home`** вида `{data:<JSON.stringify(STATE)>, updatedAt, writer}`.
- Локальный кэш: `localStorage` ключ **`home_v1`** (+ `_ts`). Синхронизация — last-write-wins
  по `updatedAt`; свои записи игнорируются по `writer` (`myId`). `permission-denied` → «Нет доступа».

## Навигация (хаб)
- **Хаб** (`active===null`): закреплённые строки Inbox и «На выходные» + сетка карточек
  категорий (иконка в акцентном цвете, прогресс, счётчик 🔴). Кнопка «Управление» → профиль.
- **Категория** (`active===key`): шапка с «‹», иконкой, именем; кнопки «списком», «править»
  (editmode), профиль; тумблеры «важность» (сортировка по приоритету) и «скрыть ✓».
  Внутри — подкатегории/заголовки/задачи.
- **Выходные** (`active==='__wk__'`): витрина, сгруппированная по категории; только чтение
  структуры, действия — на оригиналы. FAB на этом экране скрыт.
- **FAB** (`#fab`, плавающая «＋» справа внизу) → быстрый ввод (`#qsheet`): поле, выбор
  «Куда» (по умолчанию текущая категория или Inbox), приоритет, флаг «На выходные». После
  «Добавить» окно НЕ закрывается — можно накидать несколько задач подряд.

## Иконки вместо эмодзи
- Карта `P` (id → SVG-path), рендер `ic(id, style)`. Библиотека выбора — `ICON_LIB`,
  названия `ICON_NAMES`, подсказки по названию `ICON_HINTS`/`iconSuggestList()`.
- Пикер иконок — в редакторе категории/подкатегории (`#esheet`), заменяет эмодзи-пикер.
  У категории дополнительно выбор цвета (`CAT_COLORS`, `colorRow`). У заголовка-раздела
  иконки/цвета нет.
- Приоритеты рисуются точками/кольцом/молнией (`priGlyph`), флаг выходных — иконкой `calendar`.

## Приоритеты и сортировка
- Приоритет ставится в карточке задачи (`#tsheet`) и в быстром вводе. В строке — цветная
  полоска слева. Сортировка внутри подкатегории: по приоритету (🔴→🟠→⚡→🟢→без), затем
  выполненные вниз. Тумблер «важность» (`sortPri`, localStorage `sort_pri`, по умолчанию вкл).
  В режиме правки (editmode) сортировка по приоритету отключается, чтобы drag работал по
  хранимому порядку.
- «Скрыть выполненные» — `hideDone` (localStorage `hide_done`).

## Доступ и безопасность (ключевое)
- Вход: Google, **ТОЛЬКО `signInWithPopup`** (redirect на iOS/standalone даёт
  «missing initial state»), `prompt:'select_account'`, ошибка → `onSignInError`.
- **Кто имеет доступ — задаётся ТОЛЬКО в правилах Firestore** (Firebase Console →
  Firestore → Rules), НЕ в коде и НЕ в этом файле.
- **Текущее правило — wildcard** (общее с «Соберись!»): даёт доступ ко **всем** документам
  проекта разрешённым email, поэтому `checklists/home` уже покрыт — отдельное правило для
  него НЕ нужно.
  ```
  match /{document=**} {
    allow read, write: if request.auth != null &&
      request.auth.token.email in ['<email1>', '<email2>'];
  }
  ```
  Конкретный список email — только в консоли (в публичный репозиторий его НЕ кладём).
  **Чтобы добавить пользователя** — дописать его email в список этого правила
  (Console → Rules → Publish). В коде ничего менять не нужно.
- Не входящий / не из списка → `permission-denied` → экран «Нет доступа».
- Firebase `apiKey` в коде — это нормально, он не секретный; защищают правила.
- **Приватность (репозиторий публичный).** Никаких личных данных (адреса, телефоны,
  email-списки, файлы) в коде и в папке. `ТЗ-домашние-задачи.md` и `dom-zadachi.md`
  в `.gitignore`. Перед коммитом — `git status`.

## ⚠️ Обязательные правила при изменениях
1. **Менял `index.html` или `sw.js`? Подними версию кэша в `sw.js`:**
   `const CACHE='dom-vN'` → `vN+1`. Иначе у пользователей останется старая версия из кэша SW.
2. Не ломай структуру `STATE` — она сериализуется в облако. Меняешь схему — обнови `migrate()`.
3. Никаких секретов/личных данных в коде.
4. После правок — проверь, что приложение открывается и данные грузятся.
