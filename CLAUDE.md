# CLAUDE.md — контекст проекта «Дом!»

## Что это за приложение
**«Дом!»** — семейный менеджер домашних дел (PWA). Собран на движке приложения
**«Соберись!»** (https://github.com/faxbax-ctrl/abkhazia-checklist): тот же вход,
хранение, синхронизация, перетаскивание и bottom-sheet. Отличается принцип
организации (хаб категорий вместо поездок), дизайн, иконки вместо эмодзи и новые
фичи (Inbox, «На выходные», очереди-приоритеты, «Обслужить», архив категорий, поиск,
отчёт-метрики, режимы плитки/список).

- Firebase-проект: `abkhazia-checklist` (общий с «Соберись!»), но **отдельный документ**.
- Открывается как приложение на iPhone/Android и в браузере, работает офлайн,
  синхронизируется между устройствами и пользователями. Вход — Google.
- **Живой адрес:** https://faxbax-ctrl.github.io/dom-tasks/
- **Репозиторий:** https://github.com/faxbax-ctrl/dom-tasks (публичный, GitHub Pages).
- **Статус:** задеплоено; документ `checklists/home` наполнен реальными задачами
  (пользовательский контент вносится через интерфейс, в коде/репозитории его нет).

## Технологии (НЕТ сборки, НЕТ фреймворков)
- Один статический сайт: `index.html` — весь HTML, CSS и JS.
- PWA: `manifest.webmanifest` + `sw.js` (офлайн-кэш) + иконки `icon-*.png`.
- Firebase (модульный SDK v10 через CDN): Auth (Google) + Firestore (хранение/синхр.).
- Хостинг: GitHub Pages (ветка `main`, корень). Правки — прямо в файлах, без `npm build`.

## Карта файлов
- `index.html` — приложение целиком (экран входа, рендер, логика, синхронизация,
  внизу — `<script type="module">` с инициализацией Firebase).
- `sw.js` — service worker, офлайн-кэш оболочки.
- `manifest.webmanifest` — манифест PWA (имя «Дом!», иконки, `theme_color:#37478f`).
- `icon-180/192/512.png` — иконки. Регенерация из `icon.svg`:
  `rsvg-convert -w 512 icon.svg -o icon-512.png` (и 192, 180).

## Модель данных
Корень — `STATE`, один уровень категорий (никаких поездок/шаблонов):
```
STATE = { v:1, cats: [
  { key, icon, color, tab, title, intro, kind, groups: [
      { gid, emo, title, inb?, svc?, items: [ { id, ct, t, n, done, pri, wk } ] }  // подкатегория
      | { gid, sub }                                               // заголовок-раздел
  ] }
] }
```
- **Категория** `{key, icon, color, tab, title, intro, kind, groups}`: `icon` — id иконки
  из карты `P` (НЕ эмодзи), `color` из `CAT_COLORS`, `tab` — короткая подпись,
  `title` — полное имя. `kind:'inbox'` — служебная категория Inbox; обычные — без `kind`.
- **Подкатегория** `{gid, emo, title, items}` — `emo` тоже id иконки (имя историческое).
  `gid` — **стабильный идентификатор группы** (`mkGroup()`/`ngid()`), проставляется в `migrate()`.
  За него держатся свёрнутость (`openState[c.key+'-'+g.gid]`, он же `data-gk`), редакторы
  подкатегорий/заголовков и `openTaskNew`. Индексы групп «плывут» при перетаскивании и при
  вставке служебных групп — **на них завязываться нельзя**.
- **Заголовок-раздел** `{gid, sub}` — строка без пунктов.
- **Задача** `{id, ct, t, n, done, pri, wk, rec?}`: `t` заголовок, `n` комментарий, `done` галочка.
  - `ct` — **время создания** (мс). Появилось в 1.4 для сортировки «новые/старые» в окне
    «Очереди». У задач из старых версий его нет — `migrate()` достаёт его из `id`
    (`ctFromId`: `nid()` = `'i'` + `Date.now().toString(36)` + счётчик + 4 случайных символа);
    если не разбирается — `ct=0` (считается «самой старой»).
  - `pri` — **очередь**, значение ВАЛИДИРУЕТСЯ в `migrate()` (`if(!(it.pri in PRI)) it.pri=''`):
    чужое/битое значение роняло `PRI[it.pri].c` и вместе с ним весь `render()`.
    Ключи в данных не менялись, сменились смысл/подписи/цвета:
    `''`=«Без очереди» | `'red'`=«1 очередь» | `'orange'`=«2 очередь» | `'fast'`=«3 очередь» | `'green'`=«4 очередь».
  - `wk` — флаг «На выходные». `rec` — цикличность
    `{n, unit:'d|w|m|y', next:'ГГГГ-ММ-ДД', mode:'done|fixed'}`.
    **`mode`** появился в 1.5 и решает, ОТ ЧЕГО считается следующий срок (`nextRecDate`):
    `'done'` (умолчание, старое поведение) — период от момента нажатия галочки, поэтому
    новая задача не появится, пока не выполнена старая; `'fixed'` — жёсткое расписание
    от прошлого планового срока, пропущенные циклы прокручиваются вперёд до будущей даты
    (с потолком итераций и отступлением на «сегодня + период», если не сошлось).
    `migrate()` проставляет `mode='done'` всему, где он не `'fixed'`.
- **Корень STATE дополнительно**: `wkTitle`, `stats:{created,done}`, `doneLog:[{id,ts}]`
  (кап 1000), `svcLog:[{t,cat,ts,note}]` (кап 300). У категории может быть `fav:true`.
- **Настройки показа — в `localStorage`, НЕ в `STATE`** (у каждого устройства свои):
  `hide_done`, `sort_pri`, `hub_view`, **`new_top`** (новые задачи сверху/снизу — переключатель
  в профиле, `addTaskTo`), **`q_sort_new`** (порядок в окне «Очереди»), **`wk_view`**
  (витрина выходных: `cats` плитками по категориям / `list` сплошным списком по очередям),
  **`theme`** (`light|dark|system`), `seen_<uid>` (профиль-приветствие показан).
  Все переключатели собраны в профиле (`renderProfSettings` + шаблон `setSeg`); «скрыть ✓»
  и «очередь» продублированы тумблерами в шапке категории — ключи те же.
- **Цикличные («Обслужить»)**: задача живёт в подкатегории `{svc:true, title:'Цикличные'}`
  своей категории (`ensureSvcGroup`/`placeByRec`); витрина `active='__svc__'`. Подтверждение
  (`svcConfirm`): запись в `svcLog`, `rec.next` = сегодня + период.
- **Inbox** — реальная категория `kind:'inbox'`, всегда первая, удалить нельзя (`ensureInbox()`).
- **Подкатегория «Inbox»** — приёмник всего входящего ВНУТРИ каждой категории
  (`ensureInboxGroup(c)`), создаётся вверху категории (после svc-группы «Цикличные»).
  Держится на флаге **`inb:true`**, а не на названии: пользователь может её переименовать
  и перетащить куда угодно — приёмником она останется. `migrate()` усыновляет бывшую
  «Задачи» (`adoptInboxGroup`: переименование + иконка `inbox`) и создаёт группу там, где
  её нет. Сюда кладут задачу все переносы, быстрый ввод и новые задачи.
- **Архив категорий** — `STATE.archive:[]`, массив целых категорий, вынесенных из `STATE.cats`.
  Поэтому архив НЕ участвует ни в каком подсчёте (метрики, очереди, обслуживание, хаб) —
  просто не итерируется. Inbox архивировать нельзя. `deleteCategory` остался безвозвратным —
  для сохранения используется архив.
- **«На выходные»** — виртуальная витрина (`active='__wk__'`), НЕ хранится в `cats`.
  Собирает задачи с `wk===true` (`weekendItems()`); галочка действует на оригинал.
  Два режима показа (`wkSeg`, `wk_view`): по категориям и сплошным списком, где задачи
  сгруппированы по очередям 1→4→без, а категория уходит подписью под заголовок
  (`itemRow(it, sub)` — второй аргумент это готовый HTML подписи).
- **Подкатегория → категория** (`groupToCategory`, окно `#g2sheet`, кнопка-сетка в
  `.g-acts` в режиме правки). «Перенести» отдаёт ТЕ ЖЕ объекты задач (подкатегория
  исчезает из исходной категории, `ensureInboxGroup` тут же чинит приёмник);
  «Копировать» выдаёт задачам НОВЫЕ `id` — иначе две категории делили бы
  идентификаторы. Сама подкатегория становится приёмником (`inb:true`) новой
  категории. У служебной группы «Цикличные» кнопки нет.
- `MODEL` = `STATE.cats`; `active` — `null`(хаб) | `'__wk__'` | `'__svc__'` | ключ категории.

### Почему сделано именно так (не откатывать)
- **`migrate()` идемпотентна и сохраняет ВЕСЬ объект** (`s=raw; s.v=1`), а не только `cats` —
  иначе `stats`/`wkTitle`/`doneLog`/`svcLog`/`archive` сбрасывались бы при каждой загрузке и
  облачной синхронизации. Это была реальная ошибка. Также приводит `stats` к числам:
  частичный `{created}` без `done` давал `NaN` навсегда.
- **`updatedAt` монотонен**: `save()` пишет `Math.max(localUpdatedAt+1, Date.now())`. С голым
  `Date.now()` устройство с отстающими часами получало метку меньше уже принятой, и второе
  устройство молча откатывало его правки. **НЕ возвращать обратно.**
- **`__primed`**: пока не пришёл первый снапшот (или не истекли 8 с), `pushCloud()` молчит, а
  `render()` показывает «Загружаю список из облака…». Иначе после выхода/входа (кэш стёрт)
  пустое состояние затирало бы облако.
- **Ошибки записи видны**: `CLOUD.push` возвращает промис, его `.catch` красит `#cloudDot`
  (`setCloud`/`cloudLabel`). Раньше отказ (документ >1 МиБ, `permission-denied`, обрыв связи)
  уходил в unhandled rejection и пользователь ничего не узнавал.
- **Выход из аккаунта стирает локальный кэш** (`wipeLocal`) и снимает подписку (`stopCloud`):
  `localStorage` привязан к origin, а не к аккаунту. Подписку снимать обязательно — её
  `permission-denied` после выхода рисовал «Нет доступа» без кнопки входа.
- **`editmode` скоупится на `#view`** (`#view.editmode …` в CSS); на `body` он остаётся только
  ради подсветки карандаша в шапке. С правилами на `body` режим правки «протекал» в окно
  «Очереди»: появлялись ручки drag и крестики, а чекбоксы переставали работать.
- **Драг**: `attachDrag`/`detachDrag` снимают ВСЕ четыре слушателя — с `{once:true}` на window
  после каждого драга оставался висячий `pointercancel`. Драгу передаётся сам DOM-элемент из
  события: искать по `data-id` нельзя, одна задача может быть отрисована в нескольких местах
  (витрины, окно «Очереди»). Снапшот из облака во время драга откладывается
  (`pendingRemoteRender`).
- **Поиск**: результаты в отдельном скролле (`.fs-body`) — иначе поле и «Закрыть» уезжали
  при длинной выдаче. Выдача режется до `SEARCH_CAP=100`. Строка при каждом открытии
  ПУСТАЯ (`openSearch`): прошлый запрос приходилось стирать вручную. Иконка поиска
  продублирована в шапке категории, левее тумблера «очередь».
- **Шапка на десктопе**: строки шапки (`.h-row`, `.h-row2`, `.edbar`, `.bar`, `.bar-row`)
  центрируются на 760px — иначе элементы разъезжаются к краям экрана.

## Облако и хранение
- Один документ **`checklists/home`** вида `{data:<JSON.stringify(STATE)>, updatedAt, writer}`.
- Локальный кэш: `localStorage` ключ **`home_v1`** (+ `_ts`). Синхронизация — last-write-wins
  по `updatedAt`; свои записи игнорируются по `writer` (`myId`). `permission-denied` → «Нет доступа».
- Лимит документа ~1 МБ. Индикатор в профиле (`renderStorage`), `checkStorage` alert при ≥80%.
  Там же кнопка **«Скачать резервную копию»** (`exportBackup`, JSON всего `STATE`).

## Ориентиры по интерфейсу
Подробности читаются в `index.html`; здесь только то, что неочевидно.
- **Тема** (светлая / тёмная / как в системе). Все цвета — только переменные в `:root`;
  тёмная тема переопределяет их в `:root[data-theme="dark"]`, поэтому в остальном CSS
  не должно появляться «зашитых» `#fff` и т.п. Два оттенка индиго: **`--indigo`** —
  заливки (на них белый текст), **`--indigo-tx`** — акцентный ТЕКСТ и иконки
  (в тёмной теме светлее). `color-scheme` переключается там же — иначе нативные
  контролы (дата, чекбоксы, скроллбары) остаются светлыми. Тема применяется **до
  отрисовки** маленьким скриптом в `<head>` (иначе тёмная тема мигает белым);
  `applyTheme/setTheme/resolvedTheme` в основном скрипте, `system` слушает
  `prefers-color-scheme` и перекрашивается на лету. `meta[theme-color]` обновляется тоже.
- **Все bottom-sheet открываются ИЗ ЦЕНТРА экрана** (`.sheet-back{align-items:center}`
  с полями и `env(safe-area-*)`), на всех размерах, а не только на десктопе.
  Разворот на весь экран добавляет `.fullback` подложке — она снимает эти поля
  (`toggleSheetFull`, `openSheet` его сбрасывает).
- **`.sheet-card.split` — окно «шапка / прокрутка / кнопки»**: карточка становится
  flex-колонкой с `overflow:hidden`, тянется и прокручивается только `.sheet-scroll`,
  а `.sheet-acts` («ОК», «Сохранить») ВСЕГДА видны. Раньше карточка категории с
  библиотекой иконок и цветов прокручивалась целиком и «Сохранить» оказывалась за
  нижним краем. Класс стоит у `#tsheet`, `#esheet`, `#qsheet` и у всех окон-списков.
  Если добавляете в такое окно `.sheet-scroll` с inline-стилем — не затирайте
  `margin:0 -18px` из класса, иначе поля удвоятся.
- **Правка (`editmode`) — свойство ВИТРИНЫ, а не приложения, и в JS тоже.**
  Проверять надо `rowInEdit(el)` (= `el.closest('#view.editmode')`), а НЕ глобальную
  переменную `editmode`: одна и та же задача рисуется и в `#view`, и в окнах
  «Очереди»/«Выходные». С глобальной проверкой включённая на хабе правка ломала
  в «Очередях» чекбоксы (`boxTap`), открытие задачи (`itemClick`) и превращала
  долгое нажатие в драг (`onItemPointerDown`). CSS перенесли на `#view` ещё в 1.3 —
  в 1.5 то же сделали в JS.
- **Бросок задачи разрешён только внутри `.grp[data-gk]`** (`itemDragOver`): в витринах
  «Выходные»/«Очереди» соседняя строка — задача из ДРУГОЙ категории, и «перестановка»
  молча переносила бы её туда. Там же спрятана ручка драга
  (`#view.editmode .grp:not([data-gk]) .drag{display:none}`).
- **Описание задачи — обычный ТЕКСТ со списками** (никакого HTML в данных):
  `noteInput` превращает `- `/`* `/`[] ` в начале строки в `• `/`☐ `, `noteKey`
  продолжает список по Enter и выходит из него на пустом пункте, нумерация
  автоинкрементится. Развернуть на весь экран — `#nsheet` (`openNoteEditor` →
  «Сохранить» пишет обратно в `#tsNote`, фиксация в `STATE` по-прежнему по «ОК»).
  `.note` и `.vn` — `white-space:pre-line`, иначе строки списка слипались.
- **Зум выключен**: `user-scalable=no` + `touch-action:manipulation` (двойной тап) +
  `preventDefault` на `gesturestart/change/end` (Safari игнорирует мета-тег).
  Глобальный НЕпассивный `touchmove` для этого вешать НЕЛЬЗЯ — он снимает быструю
  прокрутку со всей страницы; на Android хватает мета-тега.
- **`--vvb`** — сколько пикселей низа окна перекрыто (панель Safari, клавиатура),
  считается по `visualViewport`. На него подняты FAB и тост: без этого при свайпе
  вниз кнопка «+» отлипала и уезжала за край.
- **Значения в inline-обработчиках — только в ОДИНАРНЫХ кавычках** (`onclick="f('x')"`).
  `JSON.stringify` подставлял двойные, они обрывали атрибут `onclick="…"`, и кнопка молча
  переставала работать — так сломался переключатель темы (`setSeg`). Проверять такие кнопки
  надо НАЖАТИЕМ, а не вызовом функции из консоли: вызов проходит и в сломанной разметке.
- **Меню категории** — долгое нажатие (500 мс) на плитке хаба ВНЕ режима правки
  (`onHubCardDown` → `openCatMenu`, окно `#catmenu`): Переименовать / Дублировать /
  Убрать в архив / Удалить. Архив и удаление подтверждают внутри `archiveCategory`/`deleteCategory` —
  второй `confirm` в вызывающем коде НЕ добавлять (был такой дубль в `esArchive`).
  `duplicateCategory` выдаёт копии новые `key`/`gid`/`id` — иначе две категории делили бы
  идентификаторы и удаление задачи в одной сносило бы её во второй.
  В правке долгое нажатие по-прежнему тащит карточку.
- **Иконки вместо эмодзи**: карта `P` (id → SVG-path), рендер `ic(id, style)`, библиотека
  выбора `ICON_LIB` (~85 шт), названия `ICON_NAMES`, подсказки `ICON_HINTS`/`iconSuggestList()`.
  Служебные вне библиотеки: `repeat`, `history`, `search`, `archive`, `grid`, `chart`,
  `arrowUp`, `flame`. Цветов категорий 20 (`CAT_COLORS`).
- **Шапка хаба — ОДНА строка** (`renderHeader`, `active===null`): слева логотип
  (`.brand`, слово в `<span class="tx">` — прячется на экранах ≤339px), справа
  `queueBtn()` «Очереди» → карандаш → меню `«⋯»` (`openHMenu`, попап `#hmenuBack/#hmenu`:
  Поиск / Отчёт / Архив словами) → аватар. Кнопки 40px (38px на ≤409px).
  Переключатель плитки/списка — у заголовка «Категории», не в шапке.
- **Индикатор облака — бейдж на аватаре** (`.av .cdot`, id остался `cloudDot`), отдельной
  кнопки-точки больше нет. Состояние словами — в профиле (строка кликабельна → `cloudDotTap`).
- **Режим правки — оранжевый**: карандаш заливается `--amber`, карточки и подкатегории
  получают оранжевый пунктир, под шапкой появляется полоса `edBar()` с кнопкой «Готово».
  Звезда-избранное и карандаш на карточке в правке скрыты (тап по карточке и так открывает
  редактор).
- **Очереди** рисуются номерными значками 1–4 (`priGlyph`→`.pg .lv`, цвета `--pri-*`), не точками;
  «на выходные» в строке — огонёк `flame` (`.iqb.wkflame`). Тумблер `sortPri` (`sort_pri`).
- **Порядок задач одинаков в правке и вне её.** `sortGroupItems(g)` сортирует **сам массив**
  `g.items` (стабильно: 1→2→3→4→без, выполненные вниз), а не копию для показа. Иначе при
  нажатии «править» список перетасовывался, а drag попадал не туда. Следствие: ручной порядок
  внутри одной очереди сохраняется, перенос МЕЖДУ очередями при включённом тумблере
  «очередь» откатывается — это ожидаемо, для свободного порядка тумблер выключают.
- **Окно «Очереди»** (`renderQueuesBody`): внутри каждого уровня — по `ct`, кнопка
  `#usSort` (`toggleQSort`) переключает «новые сверху» / «старые сверху». Ручного порядка
  здесь нет намеренно: список сквозной по всем категориям.
- **Удаление задачи** — единая точка `removeTask(id)`: тост «Отменить» (5 с), позиция
  запоминается через `gid`+индекс, поэтому отмена работает и после пришедшего снапшота.
  Крестик в режиме правки (`delItem`) дополнительно спрашивает `confirm` — там легко
  промахнуться; тост при этом остаётся. У категорий и подкатегорий `confirm` был и раньше.
- **Профиль**: карточка Google-аккаунта (`renderAcct` — имя/почта из `__authedUser`,
  своего поля «имя» больше нет), блок «Настройки» (`renderProfSettings`), категории,
  архив, размер документа, резервная копия, выход. Кнопки «Добавить категорию» в профиле
  нет — она на хабе.
- **Карточка категории** (`#esheet`, `esCatActs`) содержит «Убрать в архив» (`esArchive`)
  и «Удалить категорию» (`esDelete`) — двумя иконками в шапке окна, НАД полями, а не
  под кнопкой «Сохранить»; у Inbox и у новой категории блок скрыт.
  **Сначала подтверждение, потом закрытие**: `archiveCategory`/`deleteCategory`
  возвращают `true/false`, и окно закрывается только при `true`. Раньше `closeESheet()`
  стоял ДО `confirm` — «Отмена» уносила карточку вместе с несохранённым названием.
  Открыть карточку категории можно тремя путями: плитка хаба в правке, «Переименовать»
  в меню категории и верхняя кнопка внутри категории в режиме правки (`renderCat`). **Окно «Архив»** показывает ТОЛЬКО архивные категории (вернуть — с
  подтверждением, удалить навсегда — с подтверждением); убрать В архив оттуда нельзя.
- **Переносы** (`cmMoveTo`, `toggleMovePanel`) — список категорий по алфавиту (`alphaCats`);
  сам перенос в карточке происходит по «ОК» (`saveTaskSheet`), не по выбору.
- **Быстрый ввод** (`qaAdd`) после «Добавить» ЗАКРЫВАЕТ окно и показывает тост
  «Добавлено в …» (раньше оставался открытым для серии задач).
- **Прокрутка хаба** запоминается (`hubScroll`/`leaveHub`) и возвращается в `goHub()`
  синхронно после `render()`. `requestAnimationFrame` там только страховка: в фоновой
  вкладке он может не сработать вовсе.
- `renderAll()` — единая точка «перерисовать всё открытое» (вид + профиль + очереди + архив).
- `lockScroll` — счётчик + `data-open` у sheet-окон. `esc()` экранирует кавычки.
  `sw.js` кэширует только свой origin.
- **Закрытие окна по фону** — `sheetBack(event, this, closeX)`, а НЕ `if(event.target===this)`:
  окно закрывается, только если и `pointerdown`, и `click` пришлись на подложку. Иначе
  выделение текста мышью с выходом за окно закрывало окно вместе с правкой.
- **Разворот окна на весь экран** (`.grip` → `toggleSheetFull`): `.sheet-card.full` —
  `100dvh` (не `vh`: на iPhone `100vh` больше видимой области, низ уезжал за экран) +
  `env(safe-area-inset-*)`, карточка становится flex-колонкой, а тянется и прокручивается
  только блок с классом **`.sheet-scroll`** (`usBody`/`arBody`/`lsBody`/`rsBody`/`vsBody`/`fsBody`),
  чтобы заголовок, поле поиска и кнопки не уезжали. На десктопе ширина развёрнутого окна
  ограничена 820px.
- Десктоп ≥900px: сетка 3 колонки, hover, окна-sheet по центру экрана
  (`.sheet-back{align-items:center}`), а не у нижнего края.

## Доступ и безопасность (ключевое)
- Вход: Google, **ТОЛЬКО `signInWithPopup`** — redirect на iOS/standalone даёт
  «missing initial state». `prompt:'select_account'`, ошибка → `onSignInError`.
- **Кто имеет доступ — задаётся ТОЛЬКО в правилах Firestore** (Firebase Console →
  Firestore → Rules), НЕ в коде и НЕ в этом файле.
- **Текущее правило — wildcard** (общее с «Соберись!»): даёт доступ ко **всем** документам
  проекта разрешённым email, поэтому `checklists/home` уже покрыт — отдельное правило для
  него НЕ нужно.
  ```
  match /{document=**} {
    allow read, write: if request.auth != null &&
      request.auth.token.email in ['<email1>', '<email2>'];
  }
  ```
  Конкретный список email — только в консоли (в публичный репозиторий его НЕ кладём).
  **Чтобы добавить пользователя** — дописать его email в это правило (Console → Rules →
  Publish). В коде ничего менять не нужно.
- Не входящий / не из списка → `permission-denied` → экран «Нет доступа».
- Firebase `apiKey` в коде — это нормально, он не секретный; защищают правила.
- **Приватность (репозиторий публичный).** Никаких личных данных (адреса, телефоны,
  email-списки, файлы) в коде и в папке. `ТЗ-домашние-задачи.md` и `dom-zadachi.md`
  в `.gitignore`. Перед коммитом — `git status`.

## ⚠️ Обязательные правила при изменениях
1. **Менял `index.html` или `sw.js`? Подними версию кэша в `sw.js`:**
   `const CACHE='dom-vN'` → `vN+1`. Сейчас `dom-v11`. Саму страницу SW берёт
   **network-first** (кэш — только офлайн-запас), так что забытый бамп уже не оставит
   пользователя на старой версии навсегда — но версию всё равно поднимаем.
2. Не ломай структуру `STATE` — она сериализуется в облако. Меняешь схему — обнови `migrate()`.
3. Никаких секретов и личных данных в коде.
4. **Бэкап ПЕРЕД любым циклом правок — обязателен, оба вида. Делает Claude сам,
   спрашивать пользователя не надо.** До первой правки:
   - убедиться, что `git status` чистый (или закоммитить текущее);
   - **копия кода**: `mkdir -p _backup && cp index.html sw.js _backup/` с датой в
     имени (`index.html.ГГГГММДД-ЧЧММ`);
   - **копия данных** — выгрузка всего `STATE` в `_backup/dom-data-ГГГГММДД-ЧЧММ.json`
     (порядок действий ниже). Обязательна ВСЕГДА, а не только когда правки трогают
     `migrate()`: синхронизация работает по last-write-wins, откатывать нечем.
   Папка `_backup/` — в `.gitignore`, в репозиторий не уходит и содержит личные
   данные семьи: наружу (в чат, в коммит, в любой сервис) её содержимое не выносим.
   Откат: `git checkout -- index.html` или файл из `_backup/`.

   **Как снять копию данных (проверено, работает).** Данные лежат в Firestore и
   доступны только под Google-аккаунтом пользователя, поэтому идём через его Chrome
   (`claude-in-chrome`), где сессия уже восстановлена Firebase. Логинить пользователя
   самим НЕЛЬЗЯ — если сессии нет, останавливаемся и просим войти.
   1. `navigate` на https://faxbax-ctrl.github.io/dom-tasks/ , подождать ~3 с и
      проверить, что вход есть: `localStorage.getItem('home_v1')` не пуст.
   2. **Скачивание файла в автоматизированном Chrome НЕ РАБОТАЕТ** — ни кнопка
      «Скачать резервную копию», ни `exportBackup()`: файл не доезжает, `Downloads`
      остаётся пустым. Не тратить на это время.
   3. `navigator.clipboard.writeText` тоже отваливается («Document is not focused»).
      Рабочий путь — **кнопка-времянка + настоящий клик**: вставить в страницу
      кнопку, в её `onclick` положить `textarea` с `localStorage.getItem('home_v1')`,
      `select()` и `document.execCommand('copy')`, затем кликнуть по ней инструментом
      `computer` (нужен именно пользовательский жест). Кнопку после этого удалить.
   4. Забрать из буфера **обязательно в UTF-8**: `LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8
      pbpaste > _backup/dom-data-ГГГГММДД-ЧЧММ.json`. Без этих переменных `pbpaste`
      отдаёт однобайтовую кодировку и кириллица бьётся (признак: размер файла в
      байтах равен длине строки в символах).
   5. Проверить: файл парсится как JSON, число категорий/задач осмысленное.
      Затем очистить буфер (`printf '' | pbcopy`) — в нём остаются личные данные.
5. **После цикла правок — обновить этот файл.** Всё, что важно для следующей сессии
   (новые поля `STATE`, новые функции/окна, изменённые правила поведения, найденные
   грабли), записывается в CLAUDE.md тем же коммитом, что и сами правки.
   Мелочи, очевидные из кода, не дублируем.
