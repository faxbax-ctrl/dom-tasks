# CLAUDE.md — контекст проекта «Дом!»

## Что это за приложение
**«Дом!»** — семейный менеджер домашних дел (PWA). Собран на движке приложения
**«Соберись!»** (https://github.com/faxbax-ctrl/abkhazia-checklist): тот же вход,
хранение, синхронизация, перетаскивание и bottom-sheet. Отличается принцип
организации (хаб категорий вместо поездок), дизайн, иконки вместо эмодзи и новые
фичи (Inbox, «На выходные», очереди-приоритеты, «Обслужить», архив категорий, поиск,
отчёт-метрики, режимы плитки/список).

- Firebase-проект: `abkhazia-checklist` (общий с «Соберись!»), но **отдельный документ**.
- Открывается как приложение на iPhone/Android и в браузере, работает офлайн,
  синхронизируется между устройствами и пользователями. Вход — Google.
- **Живой адрес:** https://dom-zadachi.web.app/ (Firebase Hosting, сайт `dom-zadachi` в проекте
  `abkhazia-checklist`). Старый https://faxbax-ctrl.github.io/dom-tasks/ перекидывает на новый

## Технологии (НЕТ сборки, НЕТ фреймворков)
- Один статический сайт: `index.html` — весь HTML, CSS и JS.
- PWA: `manifest.webmanifest` + `sw.js` (офлайн-кэш) + иконки `icon-*.png`.
- Firebase (модульный SDK v10 через CDN): Auth (Google) + Firestore (хранение/синхр.).

## Карта файлов

  внизу — `<script type="module">` с инициализацией Firebase).

## Модель данных
Корень — `STATE`, один уровень категорий (никаких поездок/шаблонов):
```
STATE = { v:1, cats: [
  { key, icon, color, tab, title, intro, kind, groups: [
      { gid, emo, title, inb?, svc?, items: [ { id, ct, t, n, done, pri, wk } ] }  // подкатегория
      | { gid, sub }                                               // заголовок-раздел
  ] }
] }
```
- **Категория** `{key, icon, color, tab, title, intro, kind, groups}`: `icon` — id иконки
  из карты `P` (НЕ эмодзи), `color` из `CAT_COLORS`, `tab` — короткая подпись,
  `title` — полное имя. `kind:'inbox'` — служебная категория Inbox; обычные — без `kind`.
- **Подкатегория** `{gid, emo, title, items}` — `emo` тоже id иконки (имя историческое).
  `gid` — **стабильный идентификатор группы** (`mkGroup()`/`ngid()`), проставляется в `migrate()`.
  За него держатся свёрнутость (`openState[c.key+'-'+g.gid]`, он же `data-gk`), редакторы
  подкатегорий/заголовков и `openTaskNew`. Индексы групп «плывут» при перетаскивании и при
  вставке служебных групп — **на них завязываться нельзя**.
- **Заголовок-раздел** `{gid, sub}` — строка без пунктов.
- **Задача** `{id, ct, t, n, done, pri, wk, rec?}`: `t` заголовок, `n` комментарий, `done` галочка.
  - `ct` — **время создания** (мс). Появилось в 1.4 для сортировки «новые/старые» в окне
    «Очереди». У задач из старых версий его нет — `migrate()` достаёт его из `id`
    (`ctFromId`: `nid()` = `'i'` + `Date.now().toString(36)` + счётчик + 4 случайных символа);
    если не разбирается — `ct=0` (считается «самой старой»).
  - `pri` — **очередь**, значение ВАЛИДИРУЕТСЯ в `migrate()` (`if(!(it.pri in PRI)) it.pri=''`):
    чужое/битое значение роняло `PRI[it.pri].c` и вместе с ним весь `render()`.
    Ключи в данных не менялись, сменились смысл/подписи/цвета:
    `''`=«Без очереди» | `'red'`=«1 очередь» | `'orange'`=«2 очередь» | `'fast'`=«3 очередь» | `'green'`=«4 очередь».
  - `wk` — флаг «На выходные». `rec` — цикличность
    `{n, unit:'d|w|m|y', next:'ГГГГ-ММ-ДД', mode:'done|fixed'}`.
    **`mode`** появился в 1.5 и решает, ОТ ЧЕГО считается следующий срок (`nextRecDate`):
    `'done'` (умолчание, старое поведение) — период от момента нажатия галочки, поэтому
    новая задача не появится, пока не выполнена старая; `'fixed'` — жёсткое расписание
    от прошлого планового срока, пропущенные циклы прокручиваются вперёд до будущей даты
    (с потолком итераций и отступлением на «сегодня + период», если не сошлось).
    `migrate()` проставляет `mode='done'` всему, где он не `'fixed'`.
- **Корень STATE дополнительно**: `wkTitle`, `stats:{created,done}`, `doneLog:[{id,ts}]`
  (кап 1000), `svcLog:[{t,cat,ts,note}]` (кап 300). У категории может быть `fav:true`.
- **`STATE.prefs:{sortPri,newTop}`** (1.6) — ОБЩИЕ настройки, синхронизируются между
  устройствами: они меняют порядок задач В ДАННЫХ (`sortItemsIn(s)` сортирует сами
  `g.items` по `s.prefs.sortPri`, `addTaskTo` кладёт вверх/вниз). Пока «очередь» жила в `localStorage`,
  устройство с включённой «очередью» пересортировывало список и ломало ручной порядок
  на устройстве с выключенной. Глобальные `sortPri`/`newTop` — зеркало, их выставляет
  `syncModelRef()` (поэтому объявлены `var` без значения — иначе TDZ в `load()`).
  Меняются только через `setPref()` (+ `save()`); ключи `sort_pri`/`new_top` в
  `localStorage` остались лишь значением по умолчанию для `migrate()`.
- **Настройки показа тоже ОБЩИЕ** (1.16, просьба пользователя: «нажал на телефоне — так же на
  компьютере»): `STATE.prefs.hideDone` (скрыть ✓), `hubView` (`tiles|list`), `wkView` (витрина
  выходных: `cats` по категориям / `list` сплошным списком по очередям), `qNew` (порядок в окне
  «Очереди»), `theme` (`light|dark|system`; «как в системе» на каждом устройстве — по его ОС),
  `dueHide` (отпечатки скрытого блока «Пора обслужить»). Глобальные `hideDone/hubView/wkView/
  qNew/theme` — зеркало (`syncModelRef`, объявлены `var` без значения — TDZ). Меняются ТОЛЬКО
  через `setPrefV(k,v)` (→ `save()` → облако). `migrate()` заполняет недостающие поля из
  `localStorage` этого устройства (первое устройство решает), `syncModelRef` пишет их обратно
  в `localStorage` как зеркало — тема нужна скрипту в `<head>` до загрузки списка. Тема
  перекрашивается и по снапшоту (`applyTheme` из `syncModelRef`, только после `__themeReady`:
  `__mqDark` объявлен ниже `load()`). Проверено стендом: 6 переключателей с одного устройства
  применились на втором на лету, включая тему.
  В `localStorage` только своё: `seen_<uid>` (профиль-приветствие показан),
  **`auth_hint`** (`{uid,displayName,email,photoURL}` — «здесь уже входили», см. «Мгновенный старт»).
  Все переключатели собраны в профиле (`renderProfSettings` + шаблон `setSeg`); «скрыть ✓»
  и «очередь» продублированы тумблерами в шапке категории — настройка та же.
- **Цикличные («Обслужить»)**: задача живёт в подкатегории `{svc:true, title:'Цикличные'}`
  своей категории (`ensureSvcGroup`/`placeByRec`); витрина `active='__svc__'`. Подтверждение
  (`svcConfirm`): запись в `svcLog`, `rec.next` = сегодня + период.
  Любой перенос цикличной задачи (карточка, меню долгого нажатия `cmMoveTo`) кладёт её в
  «Цикличные» новой категории (`placeByRec`) и убирает опустевшую «Цикличные» старой (1.17).
  **Период месяц/год прижимается к последнему дню** (`addPeriod`, 1.17): 31.01 + 1 мес = 28.02,
  29.02 + 1 год = 28.02. Раньше `setMonth` переполнялся (31.01 → 03.03, дальше навсегда 3-е).
  Ограничение: в режиме `fixed` цепочка от 31-го дальше идёт от 28-го (якорного дня в `rec` нет).
- **Объекты обслуживания** (1.11) — `STATE.objs:[{id, ct, t, icon, ck, spec, checks:[{id,t}],
  rec:{n,unit,next,mode}, lead, needNote, log:[{id,ts,d,note,st,chk}]}]`. Это НЕ задачи: в `cats`
  не лежат, в счётчики задач и очереди-приоритеты не входят. `ck` — необязательная привязка к
  категории (туда же падает задача «Ремонт: …»), `spec` — «паспорт» (текст), `checks` — чек-лист
  осмотра, `lead` — за сколько дней до срока объект попадает в «Пора обслужить» (`dueObjs`),
  `log` — история (новые сверху, кап `OBJ_LOG_CAP=60`), `st` ∈ `OBJ_ST` (`ok|warn|bad`).
  **«По запросу»** (1.14): `rec.mode='req'` — у объекта нет срока (`objReq`), он не попадает в
  «Пора обслужить» (`objDue`), `objNextAfter` срок не двигает; в «Обслуживании» — своя секция.
  `metric` — «что записываем» (например «давление, бар»), запись истории получает `val`
  (показание). Окно отметки `#odsheet` для такого объекта — «Внести данные»: поле значения
  (`#odVal`), без значения и комментария не записывает. Поле значения показывается и у
  обычных объектов, если задан `metric`. `normObj` пропускает `'req'` и `metric`; старая
  версия приложения превратила бы `req` в `done` — поэтому обе стороны должны обновиться.
  `normObj()` вызывается в `migrate()`; id-генераторы `noid/nkid/nlid` и `OBJ_ST` объявлены
  ВЫШЕ `load()` (иначе TDZ). Витрина `active='__svc__'` («Обслуживание»): секции Просрочено /
  Пора / По графику + ниже «Повторяющиеся задачи» (старые `rec`-задачи остались для простых
  повторов). FAB там открывает редактор объекта. Окна: `#ovsheet` (просмотр, `openObjView`,
  обновляется в `renderAll` через `ovId`), `#osheet` (редактор), `#odsheet` (отметка:
  чек-лист, состояние, комментарий — обязателен при `needNote` или состоянии ≠ «в норме»,
  дата задним числом; при «Нужен ремонт» — задача в 1 очередь). Тост «Отменить» откатывает
  запись, срок и задачу. Срок: `objNextAfter` (от даты обслуживания или `nextRecDate` по графику).
  Подошедшие объекты — блок `.duebox` вверху хаба и вверху окна «Очереди». Общий журнал
  (`openSvcLog`) = `svcLog` + история объектов. `taskToObj(id)` (кнопка «Сделать объектом» в
  карточке цикличной задачи) — id объекта `'o'+id задачи`, чтобы два устройства не создали
  дубль; записи `svcLog` с тем же названием переезжают в историю.
  Поиск находит объекты (название, паспорт, чек-лист, комментарии истории) → `searchOpenObj`.
  Текст на цветных заливках (статусы, отмеченный чек-лист) — `var(--card)`, не `#fff`: в тёмной
  теме `--svc` светлый, и белый на нём не читался. Узкие экраны: `.orow` компактнее ≤409px,
  иконка объекта прячется ≤339px.
  **Слияние:** `mergeById` (присутствие по `keep3`, удалили-но-правили → оставляем, порядок
  `mergeOrder`) + `mergeObj` (поля — `mergeFields`, `checks` по id, `log` объединением).
- **Inbox** — реальная категория `kind:'inbox'`, всегда первая, удалить нельзя (`ensureInbox()`).
- **Подкатегория «Без категории»** (до 1.10 называлась «Inbox», имя — константа `INB_TITLE`;
  `migrate()` переименовывает только нетронутое «Inbox», и в архиве тоже) — приёмник всего входящего ВНУТРИ каждой категории
  (`ensureInboxGroup(c)`), создаётся вверху категории (после svc-группы «Цикличные»).
  Держится на флаге **`inb:true`**, а не на названии: пользователь может её переименовать
  и перетащить куда угодно — приёмником она останется. `migrate()` усыновляет бывшую
  «Задачи» (`adoptInboxGroup`: переименование + иконка `inbox`) и создаёт группу там, где
  её нет. Сюда кладут задачу все переносы, быстрый ввод и новые задачи.
- **Архив категорий** — `STATE.archive:[]`, массив целых категорий, вынесенных из `STATE.cats`.
  Поэтому архив НЕ участвует ни в каком подсчёте (метрики, очереди, обслуживание, хаб) —
  просто не итерируется. Inbox архивировать нельзя. `deleteCategory` остался безвозвратным —
  для сохранения используется архив.
- **«На выходные»** — виртуальная витрина (`active='__wk__'`), НЕ хранится в `cats`.
  Собирает задачи с `wk===true` (`weekendItems()`); галочка действует на оригинал.
  Два режима показа (`wkSeg`, `wk_view`): по категориям и сплошным списком, где задачи
  сгруппированы по очередям 1→4→без, а категория уходит подписью под заголовок
  (`itemRow(it, sub)` — второй аргумент это готовый HTML подписи).
- **Подкатегория → категория** (`groupToCategory`, окно `#g2sheet`, кнопка-сетка в
  `.g-acts` в режиме правки). «Перенести» отдаёт ТЕ ЖЕ объекты задач (подкатегория
  исчезает из исходной категории, `ensureInboxGroup` тут же чинит приёмник);
  «Копировать» выдаёт задачам НОВЫЕ `id` — иначе две категории делили бы
  идентификаторы. Сама подкатегория становится приёмником (`inb:true`) новой
  категории. У служебной группы «Цикличные» кнопки нет.
- `MODEL` = `STATE.cats`; `active` — `null`(хаб) | `'__wk__'` | `'__svc__'` | ключ категории.

### Почему сделано именно так (не откатывать)
- **`migrate()` идемпотентна и сохраняет ВЕСЬ объект** (`s=raw; s.v=1`), а не только `cats` —
  иначе `stats`/`wkTitle`/`doneLog`/`svcLog`/`archive` сбрасывались бы при каждой загрузке и
  облачной синхронизации. Это была реальная ошибка. Также приводит `stats` к числам:
  частичный `{created}` без `done` давал `NaN` навсегда.
- **`updatedAt` монотонен**: `save()` пишет `Math.max(localUpdatedAt+1, Date.now())`. С голым
  `Date.now()` устройство с отстающими часами получало метку меньше уже принятой, и второе
  устройство молча откатывало его правки. **НЕ возвращать обратно.**
- **`__primed`**: пока не пришёл первый снапшот, `pushCloud()` молчит, а `render()` показывает
  «Загружаю список из облака…». Иначе после выхода/входа (кэш стёрт) пустое состояние затирало
  бы облако. Таймер 8 с (`__primeTimer`) больше НЕ праймит — только меняет текст на «Нет связи»
  (`__slowCloud`): раньше он открывал пустой список с правом правки, и первая же задача уходила
  в облако с новой меткой, затирая всё. Устройства с кэшем праймятся сразу (`localUpdatedAt>0`).
- **«Документа нет» из кэша игнорируется**: `CLOUD.subscribe` передаёт `snap.metadata.fromCache`,
  и `(!d && fromCache)` — это «нет связи» (Firestore так отвечает офлайн через ~10 с), а не
  пустое облако. Раньше свежее устройство без связи пушило почти пустой список. **НЕ убирать.**
- **`__pushBlocked`**: облако ОТВЕРГЛО запись (>1 МиБ, нет прав) — снапшоты сами больше не
  пушат (иначе вечный цикл записи). Снимают `save()`, `cloudDotTap`, `startCloud`. «Нет связи»
  (`unavailable` и т.п.) — НЕ отказ: `setCloud('wait','нет связи')` + повтор через 15 с / `online`.
- **`flushPush()`** на `visibilitychange→hidden` и `pagehide`: запись отложена на 400 мс (1.15, было 900)
  (`doPush`), а iOS замораживает свёрнутую страницу. Не успела — правка всё равно в
  `localStorage` (`STATE ≠ BASE`) и уйдёт при следующем запуске.
- **Ошибки записи видны**: промис записи с `.catch`, который красит `#cloudDot`
  (`setCloud`/`cloudLabel`). Раньше отказ уходил в unhandled rejection.
- **Выход из аккаунта стирает локальный кэш** (`wipeLocal`) и снимает подписку (`stopCloud`):
  `localStorage` привязан к origin, а не к аккаунту. Подписку снимать обязательно — её
  `permission-denied` после выхода рисовал «Нет доступа» без кнопки входа.
  С 1.15 `doSignOut` спрашивает `confirm`, если есть правки, не дошедшие до облака (`isDirty()`).
- **`editmode` скоупится на `#view`** (`#view.editmode …` в CSS); на `body` он остаётся только
  ради подсветки карандаша в шапке. С правилами на `body` режим правки «протекал» в окно
  «Очереди»: появлялись ручки drag и крестики, а чекбоксы переставали работать.
- **Драг**: `attachDrag`/`detachDrag` снимают ВСЕ четыре слушателя — с `{once:true}` на window
  после каждого драга оставался висячий `pointercancel`. Драгу передаётся сам DOM-элемент из
  события: искать по `data-id` нельзя, одна задача может быть отрисована в нескольких местах
  (витрины, окно «Очереди»). Снапшот из облака во время драга откладывается
  (`pendingRemoteRender`), но STATE он подменяет сразу — поэтому драг подкатегорий/категорий
  держится за `key`/`gid` (`drag.ck/gid/key`, `target.refGid/refKey`, у `.grp`/`.sub` есть
  `data-gid`) и ищет объекты заново при броске (1.15). Раньше ссылки на объекты старого STATE
  делали бросок «в никуда». Нет цели — ничего не меняем и не сохраняем.
- **Поиск**: результаты в отдельном скролле (`.fs-body`) — иначе поле и «Закрыть» уезжали
  при длинной выдаче. Выдача режется до `SEARCH_CAP=100`. Строка при каждом открытии
  ПУСТАЯ (`openSearch`): прошлый запрос приходилось стирать вручную. Иконка поиска
  продублирована в шапке категории, левее тумблера «очередь».
- **Шапка на десктопе**: строки шапки (`.h-row`, `.h-row2`, `.edbar`, `.bar`, `.bar-row`)
  центрируются на 760px — иначе элементы разъезжаются к краям экрана.

- **Мгновенный старт** (1.6). Медленно было НЕ из-за Google: экран входа висел, пока Firebase
  не подтвердит сессию, а на iPhone/Safari/Android `getAuth()` перед этим грузит скрытый iframe
  с `*.firebaseapp.com` + gapi (`_shouldInitProactively`). Теперь: скрипт в `<head>` ставит
  `html.boot` (прячет `#lock`), если есть `auth_hint` и кэш; в конце основного скрипта —
  `__optimistic=true; __authedUser=hint; showApp()`. `onAuthChange`: тот же uid → ничего не
  делаем; `null` → `stopCloud()` + `showLogin()` (снимает `boot`). Подсказка пишется при каждом
  входе, стирается в `wipeLocal`. `initializeAuth` без popup-resolver НЕ использовать:
  `signInWithPopup` тогда ждёт iframe после тапа, и Safari блокирует всплывающее окно.
- **Ленивый iframe входа** (1.15). Firestore не начинает связь, пока Auth не ответит «кто
  вошёл», а `getAuth()` на iPhone/Safari перед ответом грузит iframe Google — это было
  0,1–1+ с на Mac и больше на телефоне при КАЖДОМ запуске. Теперь `initializeAuth` с тем же
  набором persistence, что у `getAuth()`, и `LazyPopupResolver extends browserPopupRedirectResolver`
  с `_shouldInitProactively=false`; iframe прогревается `AUTH.warm()` (= `auth._popupRedirectResolver
  ._initialize(auth)`), которую зовёт `showLogin()` и модуль при старте, если экран входа на виду.
  Замер в Safari: готовность Auth 130–1060 мс → 13–20 мс, прогрев ~130 мс. Это внутренние поля
  SDK — **при смене версии Firebase проверить `_shouldInitProactively`/`_initialize`/`_popupRedirectResolver`.**

## Облако и хранение
- Один документ **`checklists/home`** вида `{data:<JSON.stringify(STATE)>, updatedAt, writer}`.
- Локальный кэш: `localStorage` ключ **`home_v1`** (+ `_ts`, + **`_base`**). `permission-denied` → «Нет доступа».
- **Синхронизация — трёхстороннее слияние, а НЕ last-write-wins** (1.7). `BASE` (`home_v1_base`) —
  строка `data`, которая, по нашим сведениям, сейчас в облаке; `isDirty()` = `STATE ≠ BASE`.
  - **Запись — только транзакцией** (`CLOUD.sync` → `runTransaction`, `doPush`): читаем документ;
    `cur.data===BASE` → пишем свою версию, иначе `mergeStates(BASE, моя, облако)`. Одна транзакция
    за раз (`__pushing`/`__pushAgain`). Офлайн транзакция ПАДАЕТ — это нужно: прежний `setDoc`
    вставал в очередь Firestore и при появлении связи слепо затирал правки другого устройства.
    **НЕ возвращать `setDoc` для основного документа.** `CLOUD.push` остался, но не используется.
  - **Снапшот** (`onCloudSnapshot`): `data===BASE` или свой `writer` → чужих правок нет (дослать
    свои, если `isDirty`); не правили → берём облако; правили → сливаем, `BASE=облако`, пушим.
    `BASE==null` (переход со старой версии) — старое правило по `updatedAt`.
    Взяли облако, а `migrate()` дописал поля (документ от старой версии, например без `prefs`) —
    один раз пишем нормализованную версию, иначе `isDirty()` висел бы вечно.
  - **`mergeStates(B,L,R)`**: категории (вместе с архивом — «где лежит»), подкатегории по `gid`,
    задачи ГЛОБАЛЬНО по `id` (могли перенести). Поле поменяли с одной стороны — берём его, с
    обеих — локальное. Удаление побеждает, КРОМЕ задачи, которую на другой стороне правили
    (она остаётся). Задача из удалённой категории/подкатегории уходит во «Входящие». Порядок —
    `mergeOrder` (основа — версия, где порядок меняли; новые встают по соседям, в начало/конец).
    `stats` — сумма приращений, `doneLog`/`svcLog` — объединение. `orderLike` держит порядок
    ключей: иначе слияние одинаковых версий давало другую строку и лишнюю запись.
    Проверено сценариями: офлайн-правки + правки с компа, перенос + правка, архив + новая
    задача, удаление vs правка, идемпотентность (B,B,B → B байт в байт).
  - `updatedAt` по-прежнему монотонный, но решения принимаются по содержимому, не по метке.
  - **Сверка с сервером** (1.9, `pullCloud` → `CLOUD.pull` = `getDocFromServer`): при
    `visibilitychange→visible`, `focus`, `pageshow`, `online` (троттлинг 5 с) и раз в 45 с
    на экране (1.15, было 2 мин). Причина: подписка `onSnapshot` после сна Mac / долгого фона тихо умирала —
    правки с телефона не появлялись на компе до перезахода. Ответ идёт в `onCloudSnapshot`.
    Неудачная сверка повторяется (3, 6, 9, 12 с), пока окно видно (`__pullRetry`).
  - **Оживление связи** (1.15, `reviveCloud` → `CLOUD.restart` = `disableNetwork`+`enableNetwork`):
    когда сверка нашла чужую версию, о которой подписка промолчала; при возврате после >30 с
    фона; по событию `online`; после сна (тик `setInterval` 10 с пришёл с опозданием >40 с).
    Не чаще раза в 20 с и не во время своей записи; пока идёт (`__restarting`) `doPush` и
    `pullCloud` ждут, по окончании — отправка правок или сверка.
    **`__cloudSeq`** (растёт на каждом снапшоте и каждой нашей записи): если изменился, пока
    шло чтение, ответ устарел и НЕ применяется — иначе откатили бы свою же запись. Во время
    своей записи (`__pushing`/`__pushTimer`) не читаем.
- **Копии в облаке** (1.7): раз в день первое устройство кладёт `BASE` в
  `checklists/home_bk_<номер дня % 14>` (`maybeDailyBackup`, `CLOUD.backupDaily`; ячейку с
  сегодняшней датой не перезаписывает; `bk_day` в `localStorage`). Окно `#bksheet`
  (`openBackups`/`restoreBackup`, кнопка в профиле). Перед восстановлением текущий список
  уходит в **`home_bk_undo`** («До восстановления»), затем `__forceNext=true; save()` — запись
  БЕЗ слияния. Документы `home_bk_*` покрыты тем же wildcard-правилом, правки правил не нужны.
- Лимит документа ~1 МБ. Индикатор в профиле (`renderStorage`), `checkStorage` alert при ≥80%.
  Там же кнопка **«Скачать резервную копию»** (`exportBackup`, JSON всего `STATE`): на телефоне
  (`pointer:coarse`) — системное «Поделиться» с файлом (на iPhone в PWA скачивание по ссылке не
  работает), на компе — скачивание (`downloadBlob`).
- **Окна правки пишут только изменённое** (1.15): карточка задачи (`tsOrig`), редактор объекта
  (`oeOrig`/`oeRead`, у `rec` — по подполям), карточка категории/подкатегории (`esOrig`)
  запоминают значения при открытии и по «ОК» меняют только поля, которые тронули. Раньше
  «ОК» переписывал всё значениями на момент открытия, и правка с другого устройства,
  пришедшая пока окно открыто (очередь, «на выходные», срок), молча откатывалась.
- **Локальная копия пишется тройкой** (1.15, `writeLocal`): `home_v1` + `_ts` + `_base` всегда
  вместе и из одной вкладки (`save`, `persistLocal`, `setBase`). `localStorage` общий для всех
  вкладок/окон на компьютере: раньше в паре могли оказаться список одной вкладки и база
  другой, и слияние после перезапуска откатывало правки.
- **Задачу удалили на другом устройстве, пока открыта её карточка** — «ОК» сохраняет её как
  НОВУЮ задачу (новый `id`: старый числится удалённым, слияние удалило бы её снова) + тост.

## Ориентиры по интерфейсу
Подробности читаются в `index.html`; здесь только то, что неочевидно.
- **Тема** (светлая / тёмная / как в системе). Все цвета — только переменные в `:root`;
  тёмная тема переопределяет их в `:root[data-theme="dark"]`, поэтому в остальном CSS
  не должно появляться «зашитых» `#fff` и т.п. Два оттенка индиго: **`--indigo`** —
  заливки (на них белый текст), **`--indigo-tx`** — акцентный ТЕКСТ и иконки
  (в тёмной теме светлее). `color-scheme` переключается там же — иначе нативные
  контролы (дата, чекбоксы, скроллбары) остаются светлыми. Тема применяется **до
  отрисовки** маленьким скриптом в `<head>` (иначе тёмная тема мигает белым);
  `applyTheme/setTheme/resolvedTheme` в основном скрипте, `system` слушает
  `prefers-color-scheme` и перекрашивается на лету. `meta[theme-color]` обновляется тоже.
- **Все bottom-sheet открываются ИЗ ЦЕНТРА экрана** (`.sheet-back{align-items:center}`
  с полями и `env(safe-area-*)`), на всех размерах, а не только на десктопе.
  Разворот на весь экран добавляет `.fullback` подложке — она снимает эти поля
  (`toggleSheetFull`, `openSheet` его сбрасывает).
- **`.sheet-card.split` — окно «шапка / прокрутка / кнопки»**: карточка становится
  flex-колонкой с `overflow:hidden`, тянется и прокручивается только `.sheet-scroll`,
  а `.sheet-acts` («ОК», «Сохранить») ВСЕГДА видны. Раньше карточка категории с
  библиотекой иконок и цветов прокручивалась целиком и «Сохранить» оказывалась за
  нижним краем. Класс стоит у `#tsheet`, `#esheet`, `#qsheet` и у всех окон-списков.
  Если добавляете в такое окно `.sheet-scroll` с inline-стилем — не затирайте
  `margin:0 -18px` из класса, иначе поля удвоятся.
- **Правка (`editmode`) — свойство ВИТРИНЫ, а не приложения, и в JS тоже.**
  Проверять надо `rowInEdit(el)` (= `el.closest('#view.editmode')`), а НЕ глобальную
  переменную `editmode`: одна и та же задача рисуется и в `#view`, и в окнах
  «Очереди»/«Выходные». С глобальной проверкой включённая на хабе правка ломала
  в «Очередях» чекбоксы (`boxTap`), открытие задачи (`itemClick`) и превращала
  долгое нажатие в драг (`onItemPointerDown`). CSS перенесли на `#view` ещё в 1.3 —
  в 1.5 то же сделали в JS.
- **Бросок задачи разрешён только внутри `.grp[data-gk]`** (`itemDragOver`): в витринах
  «Выходные»/«Очереди» соседняя строка — задача из ДРУГОЙ категории, и «перестановка»
  молча переносила бы её туда. Там же спрятана ручка драга
  (`#view.editmode .grp:not([data-gk]) .drag{display:none}`).
- **Описание задачи — форматирование как в Заметках (1.14), но в данных по-прежнему ТЕКСТ**
  (никакого HTML в `STATE`). Строка = абзац; разметка: `# ` / `## ` — заголовок/подзаголовок,
  `• ` список, `1. ` нумерация, `☐ `/`☑ ` чек-лист (☑ — отмечен, зачёркнут), `**жирный**`,
  `*курсив*`, `__подчёркнутый__`, `~~зачёркнутый~~`. Описания старых версий читаются без
  миграции. Редактор `#tsNote`/`#nsText` — `contenteditable` (`.rt`), абзацы — `<div data-t=
  "h1|h2|ul|ol|ck">`, отметка — `data-on="1"`; `rtSet(ed,text)` / `rtGet(ed)` — текст ⇄ DOM,
  `rtNorm` держит корень списком `<div>` (каретку возвращает). Панель `.rt-bar[data-ed]`,
  кнопки работают на **`pointerdown` + `preventDefault`** — иначе фокус уходил из редактора
  (на iPhone пряталась клавиатура). B/I/U/S — `execCommand`, блоки — свои (`rtCmd`).
  Enter после заголовка — обычный текст, новый пункт чек-листа — неотмеченный (`rtKey`/`rtInput`
  через `__rtEnter`); Enter на пустом пункте и Backspace в начале снимают тип. Тап по квадратику
  (`rtClick`, первые 26px абзаца) отмечает пункт. Вставка — только текст (`rtPaste`).
  Быстрые «- », «[] », «1. », «# » срабатывают на ПОСИМВОЛЬНОМ вводе пробела.
  `<br>` в конце абзаца — заглушка пустой строки: `rtGet` её срезает (иначе каждая пустая
  строка описания удваивалась). Проверка «текст → редактор → текст» на всех реальных описаниях
  должна давать то же самое (допустимо лишь «- »→«• » и пробелы в концах строк).
  Превью в строке — `noteHtml()`, поиск — `notePlain()`. **Символов «☐/☑» в шрифтах iOS НЕТ**
  (Safari рисует квадрат с «?»): в интерфейсе квадратик чек-листа — `.nkb` (`.nkb.on` с галочкой) и
  SVG в кнопке панели; в ДАННЫХ «☐ »/«☑ » остаются как были (1.17). `noteInput`/`noteKey` остались для
  паспорта объекта (`#oeSpec`, обычный textarea). `.note`/`.vn` — `white-space:pre-line`.
- **Галочка у заголовка в карточке задачи** (1.14, `tsToggleDone`/`tsPaintDone`): срабатывает
  сразу, не по «ОК». Цикличная — через `saveTaskSheet()` и окно журнала (`openSvcDone`).
- **Зум выключен**: `user-scalable=no` + `touch-action:manipulation` (двойной тап) +
  `preventDefault` на `gesturestart/change/end` (Safari игнорирует мета-тег).
  Глобальный НЕпассивный `touchmove` для этого вешать НЕЛЬЗЯ — он снимает быструю
  прокрутку со всей страницы; на Android хватает мета-тега.
- **Окна не «ездят» за пальцем** (1.13, `sheetTouchMove`): iOS игнорирует `overflow:hidden` на
  body — если под пальцем в окне нечего прокручивать (короткая карточка объекта, подложка,
  шапка), жест уходит странице и она пружинит вместе с окном. Не-пассивный `touchmove`
  висит ТОЛЬКО на `.sheet-back` (глобальный нельзя, см. «Зум выключен»): пропускает жест,
  только если под пальцем блок с `overflow-y:auto|scroll`, который может прокрутиться в эту
  сторону (на упоре тоже глушим). Поля ввода и драг (`drag`) не трогает. Новое окно с классом
  `.sheet-back` подхватывается само (вешается при загрузке на все такие элементы в HTML).
  С 1.14 до 8px движения жест не трогаем вовсе (тап с дрожанием пальца должен стать кликом),
  а `.sheet-back{touch-action:pan-y}` + `overflow-x:hidden` у карточки и `.sheet-scroll` не дают
  окну уезжать вбок (так «ездило» окно нового объекта).
- **«Кнопки не нажимаются на телефоне» (1.14) — три причины, все закрыты:**
  1) закрывающееся окно 220 мс оставалось прозрачной подложкой и съедало тап по «назад»
  → `.sheet-back:not(.show){pointer-events:none}`; 2) тост «Отменить» (z 95) висел поверх
  кнопок «Отмена/ОК» нового окна → тапы ловит только его кнопка, а `openSheet` прячет тост;
  3) мелкие цели: `.ts-del`/`.scr-head .x` (Закрыть/Отмена) и `.bk` («назад») увеличены до 40–44px.
- **`--vvb`** — сколько пикселей низа окна перекрыто (панель Safari, клавиатура),
  считается по `visualViewport`. На него подняты FAB и тост: без этого при свайпе
  вниз кнопка «+» отлипала и уезжала за край.
- **Значения в inline-обработчиках — только в ОДИНАРНЫХ кавычках** (`onclick="f('x')"`).
  `JSON.stringify` подставлял двойные, они обрывали атрибут `onclick="…"`, и кнопка молча
  переставала работать — так сломался переключатель темы (`setSeg`). Проверять такие кнопки
  надо НАЖАТИЕМ, а не вызовом функции из консоли: вызов проходит и в сломанной разметке.
- **Меню категории** — долгое нажатие (500 мс) на плитке хаба ВНЕ режима правки
  (`onHubCardDown` → `openCatMenu`, окно `#catmenu`): Переименовать / Дублировать /
  Убрать в архив / Удалить. Архив и удаление подтверждают внутри `archiveCategory`/`deleteCategory` —
  второй `confirm` в вызывающем коде НЕ добавлять (был такой дубль в `esArchive`).
  `duplicateCategory` выдаёт копии новые `key`/`gid`/`id` — иначе две категории делили бы
  идентификаторы и удаление задачи в одной сносило бы её во второй.
  В правке долгое нажатие по-прежнему тащит карточку.
- **Иконки вместо эмодзи**: карта `P` (id → SVG-path), рендер `ic(id, style)`, библиотека
  выбора `ICON_LIB` (~147 шт с 1.14), названия `ICON_NAMES`, подсказки `ICON_HINTS`/`iconSuggestList()`.
  Служебные вне библиотеки: `repeat`, `history`, `search`, `archive`, `grid`, `chart`,
  `arrowUp`, `arrowDown`, `arrowR`, `chevR`, `plus`, `flame`. Цветов категорий 20 (`CAT_COLORS`).

## Доступ и безопасность (ключевое)
- Вход: Google, **ТОЛЬКО `signInWithPopup`** — redirect на iOS/standalone даёт
  «missing initial state». `prompt:'select_account'`, ошибка → `onSignInError`.
- **Кто имеет доступ — задаётся ТОЛЬКО в правилах Firestore** (Firebase Console →
  Firestore → Rules), НЕ в коде и НЕ в этом файле.
- **Текущее правило — wildcard** (общее с «Соберись!»): даёт доступ ко **всем** документам
  проекта разрешённым email, поэтому `checklists/home` уже покрыт — отдельное правило для
  него НЕ нужно.
  ```
  match /{document=**} {
    allow read, write: if request.auth != null &&
      request.auth.token.email in ['<email1>', '<email2>'];
  }
  ```
  Конкретный список email — только в консоли (в публичный репозиторий его НЕ кладём).
  **Чтобы добавить пользователя** — дописать его email в это правило (Console → Rules →
  Publish). В коде ничего менять не нужно.
- Не входящий / не из списка → `permission-denied` → экран «Нет доступа».
- Firebase `apiKey` в коде — это нормально, он не секретный; защищают правила.
- **Рекомендация к правилу** (ревью 1.15): добавить `&& request.auth.token.email_verified == true`.
  Сейчас включён только вход Google (там email всегда подтверждён), но если включить другой
  способ входа, без этой проверки можно зарегистрироваться с чужим email без подтверждения.
- **Данные проверяются при загрузке** (1.15, `migrate`): id/ключи — `safeId` (только буквы,
  цифры, `_`; замена детерминированная, чтобы устройства не разошлись), цвет категории —
  `COLOR_RE` (`#hex`), мусорные элементы в `items`/`groups` выбрасываются. id и цвет
  подставляются в `onclick`/`style` без экранирования — испорченный файл копии ломал бы разметку.
- **Приватность (репозиторий публичный).** Никаких личных данных (адреса, телефоны,
  email-списки, файлы) в коде и в папке. `ТЗ-домашние-задачи.md` и `dom-zadachi.md`
  в `.gitignore`. Перед коммитом — `git status`.

## ⚠️ Обязательные правила при изменениях
1. **Менял `index.html` или `sw.js`? Подними версию кэша в `sw.js`:**
   `const CACHE='dom-vN'` → `vN+1`. Сейчас `dom-v25`. Страницу SW отдаёт **из кэша сразу**
   (без ожидания сети), а свежую качает в фоне (`fetchPage`, `cache:'no-cache'`); если текст
   отличается — кладёт в кэш и шлёт окнам `page-updated`. Страница перезапускается САМА
   (`applyUpdate`): в первые 15 с после открытия или когда свёрнута, и только если ничего
   не открыто (`appIdle`: окна/профиль, фокус в поле, драг). Защита от цикла — `upd_at` в
   `sessionStorage` (не чаще раза в минуту), открытая категория возвращается (`upd_active`).
   Забытый бамп поэтому не страшен, но версию всё равно поднимаем.
   Firebase SDK кэшируется отдельно (`LIB`, cache-first по адресу с версией) — **сменили
   версию SDK в `index.html` (импорты + `modulepreload`) — поменяйте `LIB`/`LIB_PREFIX` в `sw.js`.**
   В кэш кладутся только `r.ok`-ответы (раньше разовый 404 становился офлайн-версией).
2. Не ломай структуру `STATE` — она сериализуется в облако. Меняешь схему — обнови `migrate()`.
3. Никаких секретов и личных данных в коде.
4. **Бэкап ПЕРЕД любым циклом правок — обязателен, оба вида, КАЖДЫЙ раз: код И задачи
   (данные) на момент бэкапа. Делает Claude сам, спрашивать пользователя не надо.**
   Не получилось снять данные (например, Chrome-расширение не на связи) — правки можно
   готовить локально, но **деплоить нельзя**, пока копия данных не снята. До первой правки:
   - убедиться, что `git status` чистый (или закоммитить текущее);
   - **копия кода**: `mkdir -p _backup && cp index.html sw.js _backup/` с датой в
     имени (`index.html.ГГГГММДД-ЧЧММ`);
   - **копия данных** — выгрузка всего `STATE` в `_backup/dom-data-ГГГГММДД-ЧЧММ.json`
     (порядок действий ниже). Обязательна ВСЕГДА, а не только когда правки трогают
     `migrate()`: синхронизация работает по last-write-wins, откатывать нечем.
   Папка `_backup/` — в `.gitignore`, в репозиторий не уходит и содержит личные
   данные семьи: наружу (в чат, в коммит, в любой сервис) её содержимое не выносим.
   Откат: `git checkout -- index.html` или файл из `_backup/`.

   **Как снять копию данных (проверено, работает).** Данные лежат в Firestore и
   доступны только под Google-аккаунтом пользователя, поэтому идём через его Chrome
   (`claude-in-chrome`), где сессия уже восстановлена Firebase. Логинить пользователя
   самим НЕЛЬЗЯ — если сессии нет, останавливаемся и просим войти.
   1. `navigate` на https://dom-zadachi.web.app/ , подождать ~3 с и
      проверить, что вход есть: `localStorage.getItem('home_v1')` не пуст.
   2. **Скачивание файла в автоматизированном Chrome НЕ РАБОТАЕТ** — ни кнопка
      «Скачать резервную копию», ни `exportBackup()`: файл не доезжает, `Downloads`
      остаётся пустым. Не тратить на это время.
   3. `navigator.clipboard.writeText` тоже отваливается («Document is not focused»).
      Рабочий путь — **кнопка-времянка + настоящий клик**: вставить в страницу
      кнопку, в её `onclick` положить `textarea` с `localStorage.getItem('home_v1')`,
      `select()` и `document.execCommand('copy')`, затем кликнуть по ней инструментом
      `computer` (нужен именно пользовательский жест). Кнопку после этого удалить.
      Если буфер после клика пуст — в `onclick` сделать `t.focus()` перед `select()` и
      записать результат `execCommand` в текст кнопки (так видно, сработало ли). Читать
      буфер — ТОЛЬКО после клика, не параллельно с ним.
   4. Забрать из буфера **обязательно в UTF-8**: `LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8
      pbpaste > _backup/dom-data-ГГГГММДД-ЧЧММ.json`. Без этих переменных `pbpaste`
      отдаёт однобайтовую кодировку и кириллица бьётся (признак: размер файла в
      байтах равен длине строки в символах).
   5. Проверить: файл парсится как JSON, число категорий/задач осмысленное.
      Затем очистить буфер (`printf '' | pbcopy`) — в нём остаются личные данные.
5. **После цикла правок — обновить этот файл.** Всё, что важно для следующей сессии
   (новые поля `STATE`, новые функции/окна, изменённые правила поведения, найденные
   грабли), записывается в CLAUDE.md тем же коммитом, что и сами правки.
   Мелочи, очевидные из кода, не дублируем.

## Деплой

  (`faxbax@gmail.com`); если слетит — пользователь сам делает `npx firebase-tools login`.
