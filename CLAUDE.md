# CLAUDE.md — контекст проекта для Claude Code

Этот файл Claude Code читает автоматически в начале каждой сессии. Держи его в
актуальном состоянии — и любая новая сессия сразу понимает проект.

## Что это за приложение
**«Дом!»** — семейный менеджер домашних дел (PWA). Собран на движке приложения
**«Соберись!»** (https://github.com/faxbax-ctrl/abkhazia-checklist): тот же вход,
хранение, синхронизация, перетаскивание и bottom-sheet. Отличается принцип
организации (хаб категорий вместо поездок), дизайн, иконки вместо эмодзи и новые
фичи (Inbox, «На выходные», приоритеты).

- Firebase-проект: `abkhazia-checklist` (общий с «Соберись!»), но **отдельный документ**.
- Открывается как приложение на iPhone/Android и в браузере, работает офлайн,
  синхронизируется между устройствами и пользователями. Вход — Google.
- **Живой адрес:** https://faxbax-ctrl.github.io/dom-tasks/
- **Репозиторий:** https://github.com/faxbax-ctrl/dom-tasks (публичный, GitHub Pages).
- **Статус:** задеплоено; документ `checklists/home` уже наполнен реальными задачами
  (пользовательский контент вносится через интерфейс, в коде/репозитории его нет).

## Технологии (НЕТ сборки, НЕТ фреймворков)
- Один статический сайт: `index.html` — весь HTML, CSS и JS.
- PWA: `manifest.webmanifest` + `sw.js` (офлайн-кэш) + иконки `icon-*.png`.
- Firebase (модульный SDK v10 через CDN): Auth (Google) + Firestore (хранение/синхр.).
- Хостинг: GitHub Pages (ветка `main`, корень). Правки — прямо в файлах, без `npm build`.

## Карта файлов
- `index.html` — приложение целиком (экран входа, рендер, логика, синхронизация,
  внизу — `<script type="module">` с инициализацией Firebase).
- `sw.js` — service worker, офлайн-кэш оболочки.
- `manifest.webmanifest` — манифест PWA (имя «Дом!», иконки, `theme_color:#37478f`).
- `icon-180/192/512.png` — иконки (генерируются из `icon.svg`).
- `icon.svg` — исходник иконки (домик на индиго). Регенерация PNG:
  `rsvg-convert -w 512 icon.svg -o icon-512.png` (и 192, 180).
- `CLAUDE.md` — этот файл. `README.md` — краткое описание и доступ.

## Модель данных
Корень — `STATE`, один уровень категорий (никаких поездок/шаблонов):
```
STATE = { v:1, cats: [
  { key, icon, color, tab, title, intro, kind, groups: [
      { emo, title, items: [ { id, t, n, done, pri, wk } ] }   // подкатегория
      | { sub }                                                // заголовок-раздел
  ] }
] }
```
- **Категория** `{key, icon, color, tab, title, intro, kind, groups}`:
  - `icon` — id иконки из карты `P` (НЕ эмодзи), `color` — акцентный цвет (`CAT_COLORS`),
  - `tab` — короткая подпись, `title` — полное имя,
  - `kind:'inbox'` — служебная категория Inbox (см. ниже). Обычные — без `kind`.
- **Подкатегория** `{emo, title, items}` — `emo` тоже id иконки (имя историческое).
- **Заголовок-раздел** `{sub}` — строка без пунктов.
- **Задача** `{id, t, n, done, pri, wk, rec?}`:
  - `t` заголовок, `n` комментарий, `done` галочка,
  - `pri` — **очередь** (ключи в данных не менялись, сменились смысл/подписи/цвета):
    `''`=«Без очереди» | `'red'`=«1 очередь» | `'orange'`=«2 очередь» | `'fast'`=«3 очередь» | `'green'`=«4 очередь».
    Рисуются номерными значками `priGlyph` (`.pg .lv`, цвета `--pri-*`), не точками. `PRI_NUM` даёт цифру.
  - `wk` — флаг «На выходные» (`true/false`),
  - `rec` — цикличность `{n, unit:'d|w|m|y', next:'ГГГГ-ММ-ДД'}` (нет поля = обычная).
- **Корень STATE дополнительно**: `wkTitle` (название раздела выходных, правится в
  профиле), `stats:{created,done}` (счётчики «за всё время»), `doneLog:[{id,ts}]`
  (для «выполнено на прошлых выходных», кап 1000), `svcLog:[{t,cat,ts,note}]`
  (журнал обслуживания, кап 300). У категории может быть `fav:true` (избранное,
  звезда на карточке поднимает её вверх как в Asana).
- **Цикличные («Обслужить»)**: тумблер «Повторять» в `#tsheet` (`tsRec*`,`tsReadRec`);
  задача живёт в подкатегории `{svc:true, title:'Цикличные'}` своей категории
  (`ensureSvcGroup`/`placeByRec`); витрина `active='__svc__'` (`renderService`):
  «Ближайшие» ≤7 дней + просрочка, «Всё обслуживание» по категориям; галочка →
  окно `#ssheet` с необязательным комментарием (`svcConfirm`): запись в `svcLog`,
  `rec.next` = сегодня + период; журнал — `#lsheet` (`openSvcLog`), кнопка в шапке.
- **Inbox** — реальная категория `kind:'inbox'`, всегда первая, удалить нельзя
  (`ensureInbox()`; в профиле у неё нет кнопки удаления). Быстрый ввод (FAB) кладёт сюда.
- **Подкатегория «Задачи»** — гарантированный приёмник переносов (`ensureTasksGroup(c)`):
  создаётся по требованию вверху категории (после svc-группы «Цикличные»). Все переносы
  (долгое нажатие → «Перенести в…», перенос из карточки, быстрый ввод в не-Inbox) кладут задачу сюда.
- **Архив категорий** — `STATE.archive:[]` — массив целых категорий (с группами/задачами),
  вынесенных из `STATE.cats`. Поэтому архив НЕ участвует ни в каком подсчёте (метрики, очереди,
  обслуживание, хаб) — просто не итерируется. `archiveCategory`/`restoreCategory`/`deleteArchived`;
  UI — в профиле (кнопка-архив у категории + секция «Архив категорий» с «вернуть»/«удалить навсегда»).
  Виден только в поиске при галочке «в архиве». Inbox архивировать нельзя. Удаление категории
  (`deleteCategory`) осталось безвозвратным — для сохранения используйте архив.
- **«На выходные»** — виртуальная витрина (`active='__wk__'`), НЕ хранится в `cats`.
  Собирает все задачи с `wk===true`, сгруппированные по категории (`weekendItems()`).
  Галочка/снятие флага действуют на оригинал.
- `MODEL` = `STATE.cats`; `active` — `null`(хаб) | `'__wk__'`(выходные) | ключ категории.
- **Миграция** `migrate()` идемпотентна: **сохраняет ВЕСЬ объект** (`s=raw; s.v=1`), а не только
  `cats` — иначе `stats`/`wkTitle`/`doneLog`/`svcLog`/`archive` сбрасывались бы при каждой загрузке
  и облачной синхронизации (это была реальная ошибка — исправлена). Гарантирует Inbox и `archive:[]`,
  старым задачам проставляет `pri:''`/`wk:false`.
- Облако: один документ **`checklists/home`** вида `{data:<JSON.stringify(STATE)>, updatedAt, writer}`.
- Локальный кэш: `localStorage` ключ **`home_v1`** (+ `_ts`). Синхронизация — last-write-wins
  по `updatedAt`; свои записи игнорируются по `writer` (`myId`). `permission-denied` → «Нет доступа».

## Навигация (хаб)
- **Хаб** (`active===null`) — шапка в 2 строки:
  - Строка 1 (`.h-row`): логотип «Дом!»; справа карандаш (editmode) + аватар (побольше воздуха).
  - Строка 2 (`.h-row2`): иконка поиска (`openSearch`), иконка «Отчёт» (`chart`→`openReport`,
    окно `#rsheet` с метриками: в работе/за прошлые выходные/создано/выполнено), чип «Очереди»
    (`.urg.q1`=«1 очередь · N» или `.urg.qall`=«Очереди» — постоянный вход, `openQueues`,
    окно `#usheet` со всеми уровнями 1…4+без очереди), справа иконка архива (`openArchive`).
  - Сегмент плитки/список у заголовка «Категории» (`.viewseg`, `hubView`/`setHubView`, `hub_view`;
    список — `.hub.list`). В editmode счётчики плитки прячутся (`.cl` visibility:hidden), чтобы
    карандаш не наплывал на красную точку. Пины «Входящие»/«На выходных»/«Обслужить»; звезда-избранное.
- **Категория** (`active===key`): шапка с «‹», иконкой, именем; кнопки «править» и профиль;
  тумблеры «очередь» (`sortPri`) и «скрыть ✓». «Посмотреть списком» — над списком.
- **Выходные** (`active==='__wk__'`): витрина по категориям + кнопка «править» (editmode —
  перетаскивание внутри/между категориями, удаление) + тумблер «скрыть ✓» (`hideDone`).
  **Обслужить** (`'__svc__'`): витрина, editmode запрещён. FAB на обоих скрыт.
- **Поиск** (`#fsheet`, `openSearch`/`renderSearch`): поле + галочки «в выполненных»/«в архиве»;
  результаты в отдельном скролле (`.fs-body`, чтобы поле/«Закрыть» не уезжали при длинной выдаче);
  кликабельны (`searchOpen`), архивные — только показываются (для открытия вернуть из архива).
- **Архив** (`#arsheet`, иконка на строке 2, `openArchive`/`renderArchiveBody`): две секции —
  «В архиве» (вернуть `arRestore`/удалить навсегда `arDelete`) и «Убрать в архив» (`arArchive`
  для любой активной категории). Дублирует иконку-архив в профиле — но здесь оба направления сразу.
- **Разворот окна**: тап по «грипу» (`.grip`, `toggleSheetFull`) разворачивает любое sheet на весь
  экран и обратно (`.sheet-card.full`), как в Todoist. При открытии окно всегда в обычном размере.
- **Задачи**: значок-**огонёк** (`flame`, `.iqb.wkflame`) = быстро взять на выходные (горит амбром,
  залит, когда вкл); клик по всей строке (`itemClick`, кроме кнопок) открывает задачу — важно на
  десктопе; долгое нажатие (500мс) → меню `#cmenu`: «Перенести в…» (`cmMoveOpen`/`cmMoveTo` — список
  категорий по алфавиту, задача едет в «Задачи») / Дублировать / Удалить.
- **Карточка задачи** (`#tsheet`): комментарий ~5 строк; в правке вверху блок иконок
  `#tsBtns` — «Перенести» / «Дублировать» / «Удалить». «Перенести» (`toggleMovePanel`)
  открывает выпадающий список категорий **по алфавиту** (`alphaCats`, `#mvPanel`);
  выбор ставит `tsTargetCat` + плашку `#mvNote`, сам перенос происходит по «ОК»
  (логика в `saveTaskSheet`). Чипов категорий в режиме правки НЕТ (`renderTsCat`
  рисует их только для новой задачи).
- **Выбор категории** (быстрый ввод и новая задача — унифицировано): кнопка-раскрывашка
  «Добавить в категорию» (`.catpick` + `.catpick-list`, список по алфавиту `alphaCats`),
  `renderQaPick`/`renderTsCat`. Экономит место вместо прежних чипов. Комментарий есть только
  в карточке задачи (`#tsheet`); в быстром вводе (`#qsheet`) его нет.
- **FAB** (`#fab`, плавающая «＋» справа внизу) → быстрый ввод (`#qsheet`): поле, выбор
  «Куда» (по умолчанию текущая категория или Inbox), приоритет, флаг «На выходные». После
  «Добавить» окно НЕ закрывается — можно накидать несколько задач подряд. Enter в поле
  только убирает клавиатуру (добавляет кнопка «Добавить»).

## Иконки вместо эмодзи
- Карта `P` (id → SVG-path), рендер `ic(id, style)`. Библиотека выбора — `ICON_LIB`
  (~85 шт: ремонт/инженерия/быт/мебель/медицина/типовые), названия `ICON_NAMES`,
  подсказки по названию `ICON_HINTS`/`iconSuggestList()`. Служебные вне библиотеки:
  `copy`, `calcheck`, `repeat`, `history`, `search`, `archive`, `grid`, `chart`, `arrowUp/Down`;
  `flame` — значок «на выходные» в строке задачи. Цветов категорий 20 (`CAT_COLORS`).
- Пикер иконок — в редакторе категории/подкатегории (`#esheet`), заменяет эмодзи-пикер.
  У категории дополнительно выбор цвета (`CAT_COLORS`, `colorRow`). У заголовка-раздела
  иконки/цвета нет.
- Очереди рисуются номерными значками 1–4/кольцом (`priGlyph`→`.pg .lv`), «на выходные» в строке —
  огоньком `flame` (`.iqb.wkflame`, залит при вкл).

## Очереди (бывшие приоритеты) и сортировка
- Очередь ставится в карточке задачи (`#tsheet`) и в быстром вводе номерными значками
  (`priGlyph`→`.pg .lv`). В строке — цветная полоска слева. Сортировка внутри подкатегории:
  1→2→3→4→без (`PRI_ORDER`), затем выполненные вниз. Тумблер «очередь» (`sortPri`,
  localStorage `sort_pri`, по умолчанию вкл).
  В режиме правки (editmode) сортировка по приоритету отключается, чтобы drag работал по
  хранимому порядку.
- «Скрыть выполненные» — `hideDone` (localStorage `hide_done`).

## Перенесено из «Соберись» (не откатывать)
- Плавный drag: `overPh`, `midAfter`-гистерезис, FLIP в `placePhAt`, блокировка
  iOS-скролла (`blockTouchScroll`), снапшот из облака во время драга откладывается
  (`pendingRemoteRender`); отпустил без цели — задача возвращается на место.
- `lockScroll` — счётчик + `data-open` у sheet-окон; профиль блокирует фон.
- `esc()` экранирует кавычки; sw.js кэширует только свой origin.
- Профиль: индикатор облачного документа (`renderStorage`, лимит ~1 МБ,
  `checkStorage` alert при ≥80%). Десктоп ≥900px: сетка 3 колонки, hover, **окна-sheet по центру
  экрана** (`.sheet-back{align-items:center}`), а не у нижнего края. Обе строки шапки (`.h-row`
  И `.h-row2`) центрируются на 760px — иначе иконки строки 2 разъезжаются к краям экрана.

## Доступ и безопасность (ключевое)
- Вход: Google, **ТОЛЬКО `signInWithPopup`** (redirect на iOS/standalone даёт
  «missing initial state»), `prompt:'select_account'`, ошибка → `onSignInError`.
- **Кто имеет доступ — задаётся ТОЛЬКО в правилах Firestore** (Firebase Console →
  Firestore → Rules), НЕ в коде и НЕ в этом файле.
- **Текущее правило — wildcard** (общее с «Соберись!»): даёт доступ ко **всем** документам
  проекта разрешённым email, поэтому `checklists/home` уже покрыт — отдельное правило для
  него НЕ нужно.
  ```
  match /{document=**} {
    allow read, write: if request.auth != null &&
      request.auth.token.email in ['<email1>', '<email2>'];
  }
  ```
  Конкретный список email — только в консоли (в публичный репозиторий его НЕ кладём).
  **Чтобы добавить пользователя** — дописать его email в список этого правила
  (Console → Rules → Publish). В коде ничего менять не нужно.
- Не входящий / не из списка → `permission-denied` → экран «Нет доступа».
- Firebase `apiKey` в коде — это нормально, он не секретный; защищают правила.
- **Приватность (репозиторий публичный).** Никаких личных данных (адреса, телефоны,
  email-списки, файлы) в коде и в папке. `ТЗ-домашние-задачи.md` и `dom-zadachi.md`
  в `.gitignore`. Перед коммитом — `git status`.

## ⚠️ Обязательные правила при изменениях
1. **Менял `index.html` или `sw.js`? Подними версию кэша в `sw.js`:**
   `const CACHE='dom-vN'` → `vN+1`. Иначе у пользователей останется старая версия из кэша SW.
2. Не ломай структуру `STATE` — она сериализуется в облако. Меняешь схему — обнови `migrate()`.
3. Никаких секретов/личных данных в коде.
4. После правок — проверь, что приложение открывается и данные грузятся.
